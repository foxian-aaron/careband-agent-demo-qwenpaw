# CareBand v0.2 评委 Q&A

回答原则：先说当前已证明的证据，再说限制和下一步；不把风险提示说成诊断，不把软件模拟说成硬件验收，不把模板说成真实访谈。

## 产品与价值

### Q1：这和普通健康 Dashboard 有什么不同？

CareBand 的主输出不是更多图表，而是规则先行的照护任务闭环：规范事件触发风险、同一份已验证上下文生成三角色摘要、护工人工接单完成、家属与机构同步更新。每一步有事件和任务 ID 可追溯。

### Q2：为什么要三个端，而不是一个聊天机器人？

护工需要证据与动作，家属需要克制的跟进状态，机构需要汇总与审计。三个页面消费同一份通过 Schema 的结果，减少角色间口径冲突；AI 不直接聊天决定风险或修改档案。

### Q3：你们目前真正完成了什么？

现场只列可验证项：本地前后端、SQLite、规范事件、规则、CSV/DailySnapshot、Provider/fallback、三端任务流程，以及已经通过的自动测试。实体硬件、真实访谈和真实长者试戴分别按验收表与记录数量如实说明。

## AI 与安全

### Q4：为什么用 Agent？规则已经能判断风险。

规则负责确定性风险；Agent 把档案、基线、有效事件和规则理由压缩成适合不同角色的摘要与建议动作。价值是解释和分发，不是替代安全规则。

### Q5：模型幻觉或给出诊断怎么办？

输出必须匹配固定 JSON Schema，风险等级、分数与理由必须和规则完全一致，并检查诊断/处方措辞。第一次失败带错误重试，第二次失败转确定性 Mock，界面显示 Provider、验证状态和 fallback 原因。

### Q6：QwenPaw 断网怎么办？

本地规则、任务和数据库继续运行；摘要层重试一次后明确显示 Mock fallback，不会静默换另一付费模型。现场可以主动断开 Agent 证明这条降级路径。

### Q7：未来换 GPT 是否重写业务？

不需要。Provider 只实现统一输入/输出接口；规则上下文、Schema、数据库和前端都不变。切换由配置决定，仍受相同验证和 fallback 约束。

## 数据与隐私

### Q8：Apple Watch 数据真实吗？

回答需区分：TEST001 是团队成员已授权的每日聚合证据；E001 是虚构 Demo 人物。TEST001 默认不计入机构服务对象人数和风险运营指标。没有真实证据时不能说来自长者。

### Q9：为什么不用原始 Apple Health 数据直接喂给模型？

最小必要原则。导入层先标准化成每日步数、心率聚合、睡眠、佩戴时长和质量，原始 XML 不进入 Agent 日志或提示，既降低泄露面，也让规则与测试可重复。

### Q10：如何处理位置、语音和家属权限？

位置默认区域级，语音默认只保留经授权摘要，敏感故事不自动分享。护工、家属和机构看到完成职责所需的不同最小字段；撤回与删除有单独模板。当前文书是待本地专业复核的草案，不宣称已经完成正式法律合规。

### Q11：数据不足时为什么不是“稳定”？

低佩戴时长或关键字段缺失会进入 `data_insufficient`。这阻止系统把“没有数据”误解释为“没有风险”，页面也必须说明缺什么和最后同步时间。

## 硬件与落地

### Q12：手环会测血压、血氧或自动诊断跌倒吗？

当前 ESP32-S3 原型只证明按钮到后端的事件链路，不做这些医疗测量。现成穿戴设备负责聚合数据，自制原型负责交互；跌倒若以后接入，必须带置信度并按规则验证。

### Q13：SOS 事件在断网时会不会丢？

v0.2 有最多 8 条 RAM 重试队列、指数退避和可见红灯；设备断电会丢失，这是明确限制，不是生产承诺。队列满时紫灯并明确“不成功”。正式试点前需要持久队列、连接监控和既有人工应急流程。

### Q14：实体硬件是否已经验证？

只有 BOM、接线、编译、状态机测试和 `hardware/acceptance.md` 三轮物理闭环全部有证据后才回答“已验证”。否则回答“软件侧已准备，等待用户提供实物与 COM 口”。

## 试点与证据

### Q15：有机构或护工验证吗？

按 `interview_notes` 中真实匿名记录数量回答。当前模板本身不是证据；没有访谈时直接说尚未完成，并展示邀请、同意与记录方法。

### Q16：下一步试点路径是什么？

先团队成员/工作人员封闭测试，再在明确授权、停止条件和数据删除流程下做 3–5 位志愿者测试；真实长者试戴要在硬件安全、隐私与机构审批完成后另行评估。

### Q17：成功指标是什么？

v0.2 看证据而非活跃用户：同一 CSV 重导幂等、85% 一致显示、真实 Agent/Mock 两条路径通过、E001 主线连续三次无阻断、实体按钮三次上传成功（拿到硬件后）、每个访谈结论可追溯到匿名记录。
